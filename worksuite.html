NOSMO WorkSuite.

WorkSuite groups practical execution, inspection and commissioning apps for different trades. It sits beside NOSMO BIM inside Nexus — not inside BIM.

WorkSuite applicationsNexus architectureNOSMO BIM
PurposeGive each trade a focused workflow without creating another isolated data silo.
Shared contextPeople, projects, documents, tasks, evidence, approvals and project memory come from Nexus.
BIM relationshipApplications can reference BIM objects through Nexus where the workflow needs them.

Operating pattern

Trade input → controlled work → evidence → approval → project memory.

The exact checks differ by trade, but the evidence and decision pattern can stay consistent.

Trade inputPlan, schedule, register or test requirement
Work objectDoor, system, area or task
ExecutionInstall, inspect, test or rectify
Evidence / approvalPhotos, results, defects and sign-off

Different trades, shared structure

Future applications must solve a real repeated workflow.

New trade modules are planned only where a clear combination of object, task, checks, evidence and approval justifies a dedicated app.

Connection to BIM

BIM remains a separate Nexus module.

WorkSuite applications can use BIM locations or object references, but the trade workflow remains in WorkSuite and the model context remains in NOSMO BIM.
